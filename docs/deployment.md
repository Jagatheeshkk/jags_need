# Deployment (all free tier)

Target: **Vercel Hobby** (web) → **Render Free** (API) → **Neon Free** (PostgreSQL).
Limits and sources: [free-tier-audit.md](free-tier-audit.md). Never add a payment method to
Render or Vercel if you want a hard $0 ceiling: without one, overages suspend instead of bill.

All commands are Windows PowerShell, run from the repository root unless noted.

## 0. Local development

```powershell
# Prerequisites: Python 3.12+, Node 20.9+, Docker Desktop, Git
powershell -ExecutionPolicy Bypass -File scripts\setup-local.ps1   # venv, npm ci, Playwright, .env with random secrets
docker compose up -d --build                                       # db + api + web
docker compose ps                                                  # all should be healthy/up
start http://localhost:3000                                        # create the owner account
```

If ports are taken, set `POSTGRES_HOST_PORT`, `API_HOST_PORT`, `WEB_HOST_PORT` in `.env`.

Without Docker for the app (Postgres still in Docker, or a Neon dev branch):

```powershell
docker compose up -d db
cd services\api
$env:DATABASE_URL = "postgresql://aja:<POSTGRES_PASSWORD from .env>@localhost:5432/aja"
.\.venv\Scripts\python.exe -m app.cli migrate
.\.venv\Scripts\python.exe -m app.cli seed
.\.venv\Scripts\python.exe -m app.cli seed-sample-jobs     # optional: 10 synthetic jobs
.\.venv\Scripts\uvicorn.exe app.main:app --reload --port 8000
# second terminal
cd apps\web
$env:BACKEND_URL = "http://127.0.0.1:8000"
npm run dev
```

### Refreshing jobs on a schedule (optional, local)

Free hosting sleeps, so the app checks the refresh interval when you open Job Discovery.
To refresh on a timer from your Windows laptop instead:

```powershell
$action = New-ScheduledTaskAction -Execute "docker" -Argument "compose -f E:\Jags\Jags_need\ai-job-agent\compose.yaml exec -T api python -m app.cli ingest"
$trigger = New-ScheduledTaskTrigger -Daily -At 8am
Register-ScheduledTask -TaskName "AI Job Agent refresh" -Action $action -Trigger $trigger
```

Automation can run on the same schedule (it does nothing while paused):

```powershell
$action = New-ScheduledTaskAction -Execute "docker" -Argument "compose -f E:\Jags\Jags_need\ai-job-agent\compose.yaml exec -T api python -m app.cli automate"
```

### Migrations

```powershell
cd services\api
.\.venv\Scripts\alembic.exe upgrade head                    # apply (DATABASE_URL from env)
.\.venv\Scripts\alembic.exe revision --autogenerate -m "describe change"   # after model changes
.\.venv\Scripts\alembic.exe check                           # models and migrations agree
```

The API container runs `migrate` on every start; it is idempotent.

## 1. Database: Neon Free

1. Sign up at neon.com (no card). Create a project: PostgreSQL 17, region
   **AWS Asia Pacific (Singapore)** (same region as the Render service in `render.yaml`).
2. Copy two connection strings from **Connect**:
   * **Pooled** (host contains `-pooler`) → the API's `DATABASE_URL`.
   * **Direct** (no `-pooler`) → for backups, restores and recovery drills.
3. Both must end with `?sslmode=require`.

## 2. Backend: Render Free (Blueprint)

`render.yaml` at the repository root describes the service. Free instance: **512 MB RAM,
0.1 CPU**, sleeps after 15 minutes without traffic (verified on render.com/docs on 2026-10-28).

1. Render → **New → Blueprint** → connect the GitHub repository. Render reads `render.yaml`.
2. Enter the three values it asks for (`sync: false`):
   * `DATABASE_URL`: the Neon **pooled** string.
   * `BOOTSTRAP_TOKEN`: a random value, e.g. `python -c "import secrets; print(secrets.token_urlsafe(24))"`.
     You type it once on the setup screen; keep it somewhere private.
   * `CORS_ORIGINS`: `https://<your-project>.vercel.app` (you can fill it after step 3 and redeploy).
   `SECRET_KEY` is generated by Render; `ENVIRONMENT=production`, `PYTHON_VERSION=3.13.5` and the
   rest are set by the Blueprint.
3. Apply. The start command is `python -m app.cli serve`: it migrates, seeds and serves in one
   process. `autoDeployTrigger: checksPass` deploys new commits only after GitHub CI passes.
4. Check `https://<service>.onrender.com/api/health` → `{"status":"ok","database":"ok"}`.
   If the service refuses to start, the log shows one line such as
   `Configuration error: settings: … BOOTSTRAP_TOKEN must be set in production` (values are never printed).

Manual alternative (no Blueprint): New → Web Service, Root Directory `services/api`, Build
`pip install .`, Start `python -m app.cli serve --host 0.0.0.0 --port $PORT`, Health Check
`/api/health`, Instance type Free, and the variables above plus `ENVIRONMENT=production`,
`SECRET_KEY` (48+ random characters) and `PYTHON_VERSION=3.13.5`.

## 3. Frontend: Vercel Hobby

1. Vercel → **Add New → Project** → import the repo.
2. Root Directory: `apps/web`. Framework preset: Next.js.
3. Environment variables: `BACKEND_URL=https://<service>.onrender.com`, `NEXT_TELEMETRY_DISABLED=1`.
   `BACKEND_URL` is baked into the `/api` rewrite at build time: redeploy after changing it.
4. Deploy, then put the Vercel URL into Render's `CORS_ORIGINS` if you left it empty.
5. Open `https://<project>.vercel.app/login`, enter the `BOOTSTRAP_TOKEN` and create the owner.

## 4. Verify the deployment

```powershell
powershell -ExecutionPolicy Bypass -File scripts\smoke-test.ps1 -WebUrl https://<project>.vercel.app
```

Read-only (never signs in): wakes the backend and reports how long it took, then checks the
database, security headers, that protected endpoints return 401, CSRF enforcement, hidden API
docs, `Secure` cookies and that owner setup is protected. Exit code 1 if anything fails.

Then, signed in: **Free-Tier Usage & Health** must show `Paid dependencies: none`, no `fail`,
and the database storage bar.

## 5. Measured limits (local, with Render Free's limits applied)

`scripts\resource-check.ps1` runs the API image with `--memory 512m --cpus 0.1` against a
throwaway database and drives a realistic workload (upload, refresh, scoring, resume/PDF/DOCX
generation, cover letters, automation preview, export). Results on 2026-10-28:

| Measure | Result |
|---|---|
| Cold start (container start → healthy, incl. migrations) | 27.4 s with `app.cli serve` (60.9 s with the earlier three-process start) |
| Peak memory | ~140 MB of 512 MB; no OOM kill, no restarts |
| Full workload | ~17 s; slowest calls ≈1.5 s (automation preview, first PDF render) |

On Render, add the platform's own spin-up time to the cold start; the dashboard shows
"waking up" and retries automatically. A keep-awake pinger is deliberately not included: it
would use the 750 free hours on one service and the GitHub Actions minutes of private repos.

Storage: the API reports database size against `DB_STORAGE_LIMIT_MB` (1024 for Neon Free) at
`/api/settings/usage` and on the Health page; it warns at 70% and fails readiness at 90%
(Neon blocks writes at 100%).

## 6. Backup, restore and recovery drill

```powershell
# Back up / restore (local Compose DB)
powershell -File scripts\backup-db.ps1
powershell -File scripts\restore-db.ps1 -File backups\aja-YYYYMMDD-HHMMSS.dump

# Neon (use the DIRECT host)
powershell -File scripts\backup-db.ps1 -DatabaseUrl "postgresql://USER:PW@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require"
powershell -File scripts\restore-db.ps1 -File backups\aja-....dump -DatabaseUrl "postgresql://...direct...?sslmode=require"

# Recovery drill: dump, restore into a scratch DB, compare every table, clean up
powershell -ExecutionPolicy Bypass -File scripts\recovery-drill.ps1
powershell -ExecutionPolicy Bypass -File scripts\recovery-drill.ps1 -SourceUrl "postgresql://...direct...?sslmode=require"
```

The drill never modifies the source. Verified on 2026-10-28: 21 tables and 43 rows restored
with identical counts and migration version; `-SimulateCorruption` deliberately damages the
restored copy and the drill fails as it should. Also keep the JSON export from
**Settings → Export your data**. Run a drill monthly and after schema changes.

## 7. Recovery scenarios (tested where marked)

| Event | What happens | Action |
|---|---|---|
| Render instance asleep | Cold start; UI shows "waking up" and retries | None |
| Neon compute suspended | First query slower; transient 503 retried by the UI (tested: DB stopped → 503, recovers on restart) | None |
| Server killed mid-refresh | Run marked *interrupted* after 10 min; retry allowed (tested) | Refresh again |
| Unclean shutdown of every container | Data intact on restart (happened on 2026-10-28 when Docker Desktop updated; counts and migration version verified) | Local stack restarts itself (`restart: unless-stopped`) |
| Render hours exhausted | API suspended until next month | Run the API locally (`docker compose up -d`) pointed at Neon |
| Neon storage near full | Health page warns at 70%, readiness fails at 90% | Export, delete old uploads, or move to another free Postgres |
| Provider drops its free plan | Service stops | Restore the latest dump into another free Postgres; redeploy |
